== Name

dmi_memory_load - read a region of a device or file into a buffer.

== Library

OpenDMI C library (`libopendmi`, `-lopendmi`)

== Synopsis

[source, c]
----
#include <opendmi/utils.h>

bool dmi_memory_load(
        dmi_buffer_t *buffer,
        const char   *path,
        size_t        base,
        size_t        length);
----

== Description

The `dmi_memory_load` function opens `path`, maps `length` bytes starting at
physical offset `base` into memory using `mmap`(2), copies the data into
`buffer`, then unmaps the region. Page alignment is handled internally.

The data the buffer held before is dropped, and so is whatever has been read
when the reading fails.

This is what the backends reading a table or an entry point out of physical
memory fill the buffer they are given with, see `dmi_backend_t`.

=== Parameters

`buffer`::
Buffer to read the region into.

`path`::
Path to the device or file to read (e.g. `/dev/mem`).

`base`::
Physical byte offset to start reading from.

`length`::
Number of bytes to read; must be greater than zero.

== Return value

`true` on success, `false` otherwise.

== Errors

`DMI_ERROR_NULL_ARGUMENT`::
Path is `nullptr`, or length is zero.

`DMI_ERROR_FILE_OPEN`::
Device cannot be opened.

`DMI_ERROR_FILE_MAP`::
Region cannot be mapped.

`DMI_ERROR_OUT_OF_MEMORY`::
Buffer cannot hold the data.

== Notes

Errors are raised on the context of the buffer, see `dmi_buffer_context`(3).

This function is not available on Windows.
