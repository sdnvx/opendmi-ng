== Name

dmi_dell_memory_id_entry - Identifiers of a memory module

== Library

OpenDMI C library (`libopendmi`, `-lopendmi`)
endif::[]

== Synopsis

[source, c]
----
#include <opendmi/entity/dell/memory-ids.h>

typedef struct dmi_dell_memory_id_entry {
    dmi_handle_t handle;
    dmi_binary_t manufacturer;
    dmi_binary_t serial_number;
} dmi_dell_memory_id_entry_t;
----

== Description

The `dmi_dell_memory_id_entry_t` structure holds the identifiers of a memory
module, as its serial presence detect (SPD) data holds them, and is the type of
the elements of the `modules` array of `dmi_dell_memory_ids_t`. Sockets which
hold no module usually carry bytes of `0xFF`, though some firmware repeats the
identifiers of another module there, e.g. the one of PowerEdge 1300.

The serial number is marked as private, so that `dmi_anonymize`(3) replaces
it.

=== Fields

`handle`::
Handle of the memory device (type 17) of the socket.

`manufacturer`::
Identifier of the manufacturer of the module, of 8 bytes, normally its JEDEC
identifier, whose leading bytes of `0x7F` are continuation codes, e.g. `CE` for
Samsung, `2C` for Micron, or `7F 98` for Kingston.

`serial_number`::
Serial number of the module, of 4 bytes, in the order the SPD data holds
them.

== See also

`dmi_dell_memory_ids`(3), `dmi_memory_device`(3)

== Standards

Not part of the SMBIOS specification. Defined by Dell firmware, and reverse
engineered from the data corpus.
