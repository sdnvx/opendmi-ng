= Extension modules
:sectnums!:
:sectlinks:

[#cli-modules]
Types 128 to 255 are left by the specification to the vendors, which give
them to structures of their own, so the same type means different things on
the platforms of different vendors. The structures of these types are
described by the extension modules, one for each vendor, which are enabled
for the platforms of their vendors as the data is read, or with the global
`--module` option. Structures no enabled module describes are shown as raw
data. The global `--no-auto-modules` option leaves the modules of the platform
disabled, and the modules the tool is built with are listed by
`opendmi modules`.

The platform is told from the vendor of the firmware, of the system, of the
baseboard and of the processors, which are given by the structures of types
0, 1, 2 and 4, and from the name of the product of the system.

|===

| `acer`
| Acer
| Firmware or systems of Acer

| `ami`
| AMI
| Firmware of AMI

| `apple`

| Firmware of Apple

| `dell`

| Firmware of Dell

| `hpe`
| HP and HPE

| `sun`

| Enabled with `--module` only
|===

Structures a module describes are listed by `opendmi types --module`, and
their layouts are described in the part of this manual about the
specifications. The name of a module is what the `--module` option takes,
both as a global option, which enables the module, and as a filter option of
`show`, `list` and `export`, which limits the output to the structures the
module describes.

== Modules of several vendors

Two modules may describe structures of the same type, e.g. the module of a
vendor and the one of the Intel reference code, which the firmware of any
vendor may carry. The modules enabled with `--module` take precedence over the
ones enabled for the platform, and a module enabled for the platform is left
disabled if it describes a type another enabled module describes too. The
`intel` module gives way to the other modules instead, and describes only the
types they leave free.

Some vendors place the structures of the Intel reference code at types other
than the original ones, since those are taken by structures of their own. The
modules of these vendors move the structures of the `intel` module to the
types the vendor places them at, or leave them out if the platforms of the
vendor never carry them.

Some types are given by a vendor to several structures, which are told from
each other by the data they hold, e.g. by a signature at a known offset, and a
structure which matches none of them is left as raw data.

== hpe

Structures of the HP and HPE servers, which the module is enabled for when
the name of the product of the system names a server line: ProLiant, Apollo,
Synergy or Edgeline. Workstations and laptops of HP have structures of their
own, which the module does not describe.

Some structures have changed their layouts over the generations of the
servers, which are told from the name of the product: `G1` to `G7` up to
G7, and `Gen8` onwards, with `Plus` for the refreshed ones, e.g.
`ProLiant DL360 Gen10 Plus`. Structures of these types, e.g. type 226, are
decoded by the layout of the generation of the server. Type 245 has two
layouts too, which are told by the type of the board the structure describes,
a riser of a server or one of an MHS platform. The servers give types 219 and
221 to structures of their own, and never carry the structures of the Intel
reference code, which are left out.

== intel

Structures of the Intel reference code, which the firmware of the platforms
with Intel processors carries whatever its vendor is. The module gives way to
the modules of the vendors, which give the same types to structures of their
own, and describes only the types they leave free.

The firmware lists some of these structures in group associations (type 14)
of well-known names: `$MEI` for the management engine interface,
`Firmware Version Info` for the firmware version information and
`Intel(R) Silicon View Technology` for the milestones of the Silicon View
Technology. `opendmi lint` checks that the members of these groups are the
structures the names stand for, wherever the vendor places them.

[cols="1,3,5"]
|===
| Type | Code | Name

| 130 | `intel-amt`  | Intel Active Management Technology information
| 131 | `intel-vpro` | Intel vPro information
| 219 | `intel-mei`  | Intel Management Engine interface information
| 221 | `intel-fvi`  | Intel firmware version information
| 222 | `intel-svt`  | Intel Silicon View Technology milestones
|===
