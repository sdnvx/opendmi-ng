= HP/HPE DIMM Location Record (Type 202)
:sectnums:
:sectlinks:

Source: dmidecode, `dmioem.c`, and the dumps of the data corpus.

Tells where the DIMM socket of a memory device (type 17) is: the memory board,
the processor and the channel it belongs to. There is a record for each
socket, including the ones of the memory boards which are not installed. The
structure has grown with the generations of the servers, and the older ones
end after the DIMM number. dmidecode decodes the structure from Gen9 onwards,
while the older servers of the data corpus carry the same layout.

| `BYTE`

| 1-based number of the DIMM

| 1-based number of the processor, `0xFF` if not shown

| `BYTE`

| 1-based logical number of the DIMM, as ACPI numbers it

|

| `BYTE`

| 2.0+
| Device Name
| `BYTE`
| `STRING`

| `0x0E`
| 2.0+
| Memory Channel Number
| `BYTE`
| `NUMBER`

| `0x0F`
| 2.0+
| IE DIMM Number
| `BYTE`
| `NUMBER`
| 0-based number of the DIMM, as the Innovation Engine reports it, `0xFF` if not supported. Reserved from Gen12 onwards

| `0x10`
| 2.0+
| IE PLDM ID
| `BYTE`
| `NUMBER`
| Sensor ID of the Innovation Engine, `0xFF` if not supported. Reserved from Gen12 onwards

| `0x11`
| 2.0+
| Vendor ID
| `WORD`

| `0x13`
| 2.0+

| `WORD`
| `NUMBER`
| Product ID code of the module, NVDIMMs only

| `0x15`
| 2.0+
| Controller Vendor ID
| `WORD`
| `NUMBER`
| Manufacturer ID code of the controller, NVDIMMs only, as the SPD gives it: the number of continuation codes in the low byte, whose bit 7 is a parity bit, and the JEP106 code in the high byte

| `0x17`
| 2.0+
| Controller Device ID
| `WORD`
| `NUMBER`
| Product ID code of the controller, NVDIMMs only

| `0x19`
| 2.0+
| Interleave
| `BYTE`
| `NUMBER`
| 1-based interleave set within the processor

| `0x1A`
| 2.0+
| Part Number
| `BYTE`
| `STRING`
| HPE part number, from the OEM area of the SPD

| `0x1B`
| 2.0+
| DIMM Index
| `BYTE`
| `NUMBER`
| 0-based index of the DIMM within its channel, present in the structures of 28 bytes or more
