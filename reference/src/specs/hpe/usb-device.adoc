= HP/HPE USB Device Correlation Record (Type 239)
:sectnums:
:sectlinks:

Source: dmidecode, `dmioem.c`. No dumps of the data corpus hold the structure.

Describes a USB device the firmware has found at boot on a USB port (type
238), and the UEFI boot entries naming it. Devices plugged in later are not
described. The structure is decoded from Gen9 onwards, UEFI firmware only.

The codes are the ones the USB Implementers Forum defines for the classes,
named the way dmidecode names them. The codes of the other classes are shown
as they are.

[#hpe-usb-storage-subclasses, reftext=Mass storage subclasses]
.Mass storage subclass
[width=100%, cols="1,4"]
|===
| Value | Meaning

| `0x00` | SCSI command set not reported
| `0x01` | Reduced block commands (RBC)
| `0x02` | ATAPI
| `0x03` | QIC-157, obsolete
| `0x04` | USB floppy interface (UFI)
| `0x05` | SFF-8070i, obsolete
| `0x06` | SCSI transparent command set
| `0x07` | LSD FS
| `0x08` | IEEE 1667
| `0xFF` | Vendor-specific
|===

Subclasses `0x09` to `0xFE` are reserved.

[#hpe-usb-storage-protocols, reftext=Mass storage protocols]
.Mass storage protocol
[width=100%, cols="1,4"]
|===
| Value | Meaning

| `0x00` | Control/bulk/interrupt transport with command completion interrupt
| `0x01` | Control/bulk/interrupt transport without command completion interrupt
| `0x02` | Obsolete
| `0x50` | Bulk-only transport
| `0x62` | USB attached SCSI (UAS)
| `0xFF` | Vendor-specific
|===

[#hpe-usb-hub-protocols, reftext=Hub protocols]
.Hub protocol
[width=100%, cols="1,4"]
|===
| Value | Meaning

| `0x00` | Full speed
| `0x01` | Hi-speed with a single transaction translator
| `0x02` | Hi-speed with multiple transaction translators
|===
